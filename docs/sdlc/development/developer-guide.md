<!-- sdlc:auto:start overview -->
Mini Todo is a minimal to-do list application generated by the Quorq AI SDLC platform, delivered as two separate apps in one repo: a Vite + React 19 single-page frontend containing the fully approved, reviewed screens (currently running on seeded sample data, not yet wired to the backend), and a FastAPI 0.115 backend that at this stage only exposes a health check and a seeded-user auth endpoint (/auth/login, /auth/me) as scaffolding, with all other routes to be added once an architecture is approved. The backend persists data via SQLAlchemy models managed by Alembic migrations, defaulting to a local SQLite file but configurable via DATABASE_URL (e.g. PostgreSQL in Docker or in CI/tests).
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js (for the frontend, Vite 6 / React 19 toolchain)
- Python 3.12 (matches backend/Dockerfile base image)
- pip (Python package installer)
- Docker and Docker Compose (optional, for the PostgreSQL service in docker-compose.yml)
- PostgreSQL 16 (required to run backend pytest suite, per TESTING.md)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. Clone the repository
2. Copy the environment template: cp .env.example .env, and fill in values as needed
3. Backend: cd backend
4. Create and activate a virtual environment, e.g. python -m venv .venv && source .venv/bin/activate
5. Install backend dependencies: pip install -r requirements.txt
6. Start the backend: uvicorn app.main:app --reload (uses a local SQLite file by default; migrations run automatically on startup)
7. In a new shell, Frontend: cd frontend
8. Install frontend dependencies: npm install
9. Start the frontend dev server: npm run dev
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend Pydantic models extend a shared ApiModel base so JSON payloads use camelCase while Python code stays snake_case (app/api_model.py)
- One FastAPI router per architecture component that owns endpoints (backend/app/routers)
- Unimplemented generated routes return a typed StubResponse rather than failing, keeping the service startable and its OpenAPI spec complete
- Database schema is owned entirely by Alembic migrations (backend/alembic/versions), never by SQLAlchemy create_all
- DATABASE_URL controls the backend database: defaults to local SQLite, set to PostgreSQL for tests/deployment
- CORS allowed origins are controlled via the ALLOWED_ORIGINS env var, falling back to the local Vite dev origins
- Frontend screens live one module per approved screen under src/screens, built against the shared component/icon vocabulary in src/lib/ui.tsx and src/lib/icons.tsx
- Frontend API calls go only through the generated client (src/api/client.ts, from npm run gen:api), not raw fetch
- Session auth token is stored in localStorage and sent as a bearer token on API calls
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| `pytest` fails or can't connect to a database | The backend test suite requires PostgreSQL; set DATABASE_URL to a reachable Postgres instance (see docker-compose.yml for a local one) as described in TESTING.md |
| Frontend calls to the backend are blocked by CORS | Set the backend's ALLOWED_ORIGINS env var to include the frontend's origin, or rely on the default dev origins (http://localhost:5173) |
| Backend fails to start with an error about alembic.ini missing | Ensure alembic.ini and the alembic/ directory remain beside backend/app/ (both are copied into the Docker image and required at startup) |
| `npm run build` succeeds but the app breaks in a way `tsc` would have caught | Run `npm run typecheck` separately, since build does not typecheck |
| Playwright e2e tests fail to launch a browser | Run `npm run test:e2e:install` first to fetch the Chromium browser |
